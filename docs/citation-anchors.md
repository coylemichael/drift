# Citation anchors (per artifact)

Part of [Drift](../README.md). How `path:line` citations in artifacts are
anchored at publication and graded at pickup.

An artifact's `path:line` references rot as the code moves on, and a reading
session cannot tell a current claim from a stale one. At publication,
`drift_publish` records an anchor per citation in the artifact's frontmatter:
the range, a content hash of the cited lines (trailing whitespace stripped),
and the first and last lines as a search needle. When `/drift` or an automatic
continuation picks an artifact up, `scripts/check-staleness.py` grades every
citation against the tree and a single note tells the session what still
holds: `fresh` is proven by hash; `moved` is located and forwarded to its new
line or file; `changed` reports a difflib similarity; `gone` and `uncertain`
(no recorded commit, or anchored over uncommitted changes) say exactly what
could not be verified. Artifacts published before anchors existed are graded
heuristically from their recorded `git_commit`; partial sets use `mixed` mode
rather than describing every citation as exact. Capture coverage is reported
separately from these freshness verdicts. The check is a report, never a
gate: it blocks nothing, writes nothing, and a checker failure degrades to one
"unavailable" note. Each check also appends one line to a local usefulness
ledger — `<agent dir>/drift/citation-metrics.jsonl`, verdict counts, mode and
artifact date, never in a repository — so the feature's exposure and the
corpus's rot rate can be measured over time. The checker also runs standalone:

```sh
python3 -I scripts/check-staleness.py drift/<feature>/<artifact>.md [<repo>]
```

## Deterministic capture coverage

New publisher snapshots always include `anchor_coverage`, even when `anchors` is
absent. Its fields are generated by code, not supplied by the model:

| Status | Meaning |
| --- | --- |
| `not-applicable` | Zero unique recognized numeric references; no anchors expected. |
| `complete` | Every recognized numeric reference was captured. |
| `partial` | At least one recognized numeric reference was skipped, including zero captured. |
| `not-recorded` | Reader result for absent legacy/manual metadata; do not infer complete capture. |
| `invalid` | Reader result for malformed or inconsistent metadata; coverage is unknown. |

For a symbol-only handoff, the stored metadata is explicit:

```yaml
anchor_coverage: {"status":"not-applicable","eligible":0,"captured":0,"skipped_count":0,"skipped_by_reason":{},"skipped":[]}
```

`eligible` counts unique supported numeric references (`path:line`, ranges and
backticked bare continuations), including recognized invalid ranges. Repeated
references are counted once. A reference such as `lib/state.ts: readArtifactCatalog()`
is symbolic and is not eligible; no fabricated line numbers are required.
Unsupported reference syntax and references the model never wrote cannot be
accounted for by this grammar. Coverage is not a completeness check of the prose.

`captured + skipped_count = eligible`. `skipped_by_reason` accounts for every skip:
`file-not-found`, `not-a-file`, `file-too-large` (over 2 MiB), `invalid-range`
(including an end past EOF), `unsafe-path`, `read-error`, or `cap-reached`.
Managed symlinks/junctions are not followed for capture. The existing capture cap
is 100 anchors; cap-limited references are recorded as not attempted, not assumed
missing or invalid. To keep metadata bounded, `skipped` stores the first 25
examples, each reference limited to 512 characters; longer labels carry
`reference_truncated: true`. Totals/by-reason counts include unsampled references.

The checker validates recorded counts against the current artifact body and
anchor payload, and reports inconsistent data without rewriting the artifact or
blocking pickup. `/drift` and continuation notes state coverage even for zero
numeric citations or legacy metadata. A failed checker, or an older reader response
without coverage fields, is reader-unavailable—not evidence that the artifact was
published without coverage. `complete` is **capture completeness only**:
dirty anchors still grade `uncertain`, captured citations can later become
`changed` or `gone`, and an anchor does not prove a behavioral claim or test result.

Reload a running Pi extension to activate new publisher fields. Existing
artifacts and already-persisted pending publications are never backfilled or
recaptured on retry; they remain `not-recorded` when the metadata is absent.
Full deterministic handoff rendering and anchor-payload compaction are separate
changes, not part of this accounting feature.
