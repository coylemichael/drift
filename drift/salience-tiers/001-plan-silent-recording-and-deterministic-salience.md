## Objective

Make Drift's recording always-on but silent, with the full model-facing lifecycle context appearing only on deterministic engagement signals — and make Drift attach automatically when a repository appears in the launch directory after session start.

## Source Research

None on disk. In-session code analysis at commit `e871e2fae8a243ab6e7c1abf70b5fd1b69534dd1` (2026-10-12), prompted by two field transcripts: a session launched in an empty folder that cloned a repo and could never attach Drift (`drift_worktree` failed until restart), and a second session whose agent re-litigated Drift bookkeeping in six separate thinking blocks during a task that needed no artifacts. Findings are embedded in Key Files; verify line references against that commit before relying on them.

## Starting Point

Start with the record schema (`engaged` field) in `lib/state.ts` — every other task reads or writes it. Then the extension-side signals, then context tiering last, since it consumes both. The re-probe fix (task 3) is independent of tasks 1–2 and can be done in parallel.

## Implementation Sequence

1. **Schema — `engaged` on RecordData** (`lib/state.ts:40-61`): optional `engaged?: { at: string; reason: string }`, record-level only (survives worktree adoption; not added to `snapshotKeys`). Accept it in `Records.read()` validation; reject malformed values. Add `Records.engage(reason)` — under the record lock via `update()`, no-op when already set. Verify: round-trip + rejection tests in `tests/drift.test.ts`; old records without the field stay valid.
2. **Quiet context variant** (`lib/state.ts:590`): add `Records.contextQuiet()` producing ≤3 lines — record path/session/interval, repo anchor + artifact store, and "Drift is recording this session silently; no action needed. Full lifecycle guidance appears when work or Drift use begins." Keep `context()` as the engaged variant.
3. **Re-probe for late-appearing repos** (`extensions/drift.ts:52-81`): when `ready` resolves `undefined`, clear it — only if it is still the current promise and `key` is unchanged — so the next `store()` call re-runs `Records.open`. The per-turn context event then attaches automatically after a mid-session clone. Rewrite the `:183` error to cover both actions and the retry: "Drift found no Git repository at Pi's launch directory (&lt;cwd&gt;). If one was created or cloned here after launch, retry this call." Verify: runtime test — non-repo dir → inactive; `git init`; next turn → attached.
4. **Explicit-intent engagement** (`extensions/drift.ts`): call `engage()` from the `/drift` rewrite (:21-32), every `drift-*` command (:250, :270, :290, :309, :436), `drift_worktree` adopt (:181-193), and `drift_publish` (:486+). Default: any explicit Drift invocation engages, including read-only status forms (see Open Questions).
5. **Attach-time repo signals** (in `store()`'s open path, after `Records.open`): engage immediately when any of: artifact store non-empty (new `hasArtifacts(repo)` in `lib/artifacts.ts` scanning `<store>/drift/*/NNN-*.md`); `.drift.json` exists (`exists()`, not `driftConfig()`); sibling session records exist for this repo hash in the records root; or the (resumed) record already has receipts, `completed`, or `history`. Verify: fixture repos exercising each signal.
6. **Work-based engagement at checkpoints**: after `checkpointIn` (or in the extension's `checkpoint()`/`agent_settled` path), engage when `checkpoint.files` minus `drift/`-prefixed paths is non-empty or `checkpoint.commits` is non-empty (mirror the `:609` filter). Lazy by design: tourism stays quiet; the first real edit escalates on the next settled turn. Verify: edit a file in a quiet fixture → next checkpoint engages.
7. **Tiered, stable injection** (`extensions/drift.ts:346-379`): no repo → one line: "Drift is inactive: no Git repository at Pi's working directory. No action needed; Drift attaches automatically if a repository appears here. Do not claim a measured baseline." Repo + quiet → `contextQuiet()`. Engaged → current full content including the changelog and worktree-adoption lines. Stability: if the existing `drift-context` message content is identical, return `event.messages` unchanged (original position and timestamp); replace-and-append only when content changes. Error path (:366-371) unchanged. Verify: runtime test asserting tier selection and message identity across unchanged turns.
8. **Tests and checks**: new cases in `tests/drift.test.ts` (schema, signals, hysteresis: engaged persists across reopen/adoption) and `tests/pi-runtime.test.ts` (re-probe, tiers, stable injection). Run the full suite plus `tsc`.
9. **Docs + changelog**: grep `docs/` and `README.md` for descriptions of the injected lifecycle context and the inactive message; update for tiers and late attach. Publish the implementation handoff with a `changelog` entry (section: Changed) covering both the tiers and the late-attach fix.

Disjoint scopes: task 3 is independent of 1–2; tasks 4–6 depend on 1; task 7 depends on 2 and benefits from 3–6 being in place for testing.

## Decisions & Constraints

- **Gate salience, not recording.** Records, baselines, and checkpoints are always established exactly as today; tiers change only the model-facing context.
- **Deterministic, binary signals only.** No turn counts, token thresholds, or model judgement. Hysteresis: once engaged, a record never de-engages.
- A fresh clone of a repo that ships tracked `drift/` artifacts **does** engage — surfacing the navigation table is the point when artifacts exist.
- `engaged` is record-level and backward-tolerated: `Records.read()` does not reject unknown record-level fields, and the snapshot allowlist is untouched.
- `promptGuidelines` (`extensions/drift.ts:467`) stays as-is — static, small, out of scope.
- The quiet tier adds no per-turn git work beyond what checkpoints already do.
- On mid-session attach, emit a one-time `ctx.ui.notify` ("Drift attached to <repo>; recording silently") — user-visible, not model-visible.

## Open Questions

- Should read-only invocations (`drift_worktree status`, `/drift-changelog status`) engage? Sequence default: yes — any explicit reach for Drift is intent, and the rule stays simple. Flip to action-only if quieter behavior is preferred.
- Mid-turn attach ordering: with re-probe, the inactive line is replaced by the quiet line in-place on the turn after the clone. Confirm this reads cleanly in a live transcript; if the swap itself proves distracting, the quiet line's content should subsume the inactive line's wording so the diff is minimal.
