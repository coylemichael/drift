# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added

- **Profile-directed Pi handoff continuation.** Handoff publication can store a portable `next_session_profile`; `drift-continue drift/<feature>/<NNN>-handoff-<description>.md` validates that local artifact, resolves its explicitly configured model profile, selects the model and optional thinking level before sending a continuation prompt, and fails without inference when routing cannot be resolved. Global/profile-local mappings deliberately keep provider/model choices out of portable artifacts. A successful profiled handoff now queues the next fresh Pi session automatically; manual `drift-continue` input is recovery-only.
- **User decision checkpoints.** Drift now stops for explicit user direction on genuine requirement ambiguity, material scope/plan changes, public-contract/data-model changes, security/destructive/external-cost risks, priority changes, and reversals of accepted decisions. Routine constrained implementation details remain agent decisions, and a pending user decision never triggers automatic continuation.

### Fixed

- Profile mappings now document and diagnose the difference between Pi catalog model IDs and picker labels. `drift-continue` resolves IDs such as `claude-opus-5`; `pi --list-models` is the authoritative local list.
- `drift_publish` treats blank optional artifact references as absent instead of rejecting `source_research: ""` or `previous_handoff: ""`. Non-empty references remain strictly validated. Retry guidance distinguishes invalid arguments from a recoverable pending publication; runtime fixtures now exercise research and handoff calls with explicit empty optional fields.

### Changed

- **Portable skills, Pi-focused automation.** A local Pi package replaces the multi-agent installer and legacy lifecycle commands. Native Pi events own durable starting records, context injection, checkpoints, resume identity and a `drift_publish` artifact tool. The model still writes the meaningful content; code owns metadata, numbering, the canonical index and completion receipts.
- Pi records use the configured Pi agent directory. Handoff completion does not delete the conversation or baseline; receipts prevent duplicate publication, and a later working prompt begins a new interval. Teardown checkpoints rather than assuming an ACP thread permanently ended.
- Focused Node tests cover record/publication invariants and actual offline Pi RPC/ACP behavior. The shared Python index renderer remains and gains a non-writing `--stdout` mode. Current setup and testing instructions live in README.

### Removed

- Maintained Claude/Copilot/native-Zed automation, `install.py`, legacy hook scripts and harness smoke suites, and `TESTING.md`. Skill-only operation in other agents remains supported. Remove only owned legacy registrations before retiring their script paths; preserve old records and artifacts.

## Retired integration experiments (previously unreleased)

The entries below describe the superseded multi-agent implementation, not the current installation or supported automation.

### Added

- `TESTING.md` — separates offline regressions, real ACP lifecycle checks and a manual two-thread Pi handoff/resume acceptance exercise. README names Pi's current skill/manual support without claiming an automatic adapter, and keeps the legacy paid Claude smoke test out of the default test path.
- **Native Copilot CLI hooks, including Zed's Copilot ACP threads.** `install.py --copilot` installs the skill in `~/.copilot/skills/drift` and direct `exec`/`args` hooks in `~/.copilot/hooks/drift.json`, respecting `COPILOT_HOME`. Detection, dry runs, checks, backups, idempotent updates and scoped uninstall are supported without editing Copilot's user settings, Claude settings or Zed rules. The scripts accept Copilot's camelCase payload and return top-level `additionalContext`; this is harness-driven, not an AGENTS.md workaround.
- `scripts/test-hooks.py` — offline stdlib regression coverage for both payload formats, lifecycle baselines, parallel record isolation and installer behavior. `scripts/smoke-test-copilot.py` exercises the real Copilot ACP binary with a loopback model stub and temporary profile/repo, including model-context injection and multi-turn resume, without external model calls or real user state.
- `scripts/smoke-test-claude.py` — equivalent real Claude ACP coverage with a local Anthropic protocol stub: installed skill advertisement, startup context, exact turn/resume baselines, final-close capture and unchanged-record removal. Shared ACP helpers isolate credentials and provider/configuration overrides. Measured with Claude ACP 0.75.1 / Claude Code 2.1.257: final hooks finish after the ACP close response; Copilot CLI 1.0.83 instead leaves its turn checkpoint.
- Explicit dual-ACP Zed setup instructions (`install.py --claude --copilot`), including fresh bundled-agent installations without CLIs on `PATH`, scoped checks/removal, and the distinction from the native `--zed` fallback. No Zed patch or special native profile is required.
- **Session hooks — Drift's continuity no longer depends on anyone remembering to ask for it.** `scripts/hooks/session-start.py` opens a record at `~/.claude/drift-sessions/<repo>/<session-id>.json` holding the session's real start time, branch and commit, and tells the session which Drift features are open, newest first, with the latest artifact and status for each. `scripts/hooks/session-end.py` closes it with the commits and files the session touched, deleting the record outright when nothing changed. `scripts/hooks/session_state.py` holds the shared record shape and reuses `build-index.py`'s frontmatter parsing rather than re-implementing it. The reason this is a hook and not prompt text: a skill loads when the model reaches for it, so nothing in `SKILL.md` can run at session start. The reason it exists at all: the agent asked to write a handoff is at the end of its context window with the session's beginning summarised away — the worst-placed writer in the workflow, and the source of the fabricated timestamps recorded below. The record moves that metadata to the moment it was true. On a compaction or a context clear the record is kept and only its context restated, since the session's start has not moved. Both hooks always exit 0, because a non-zero exit from `SessionStart` blocks the session from starting.
- **Orphan handoffs.** A record that outlives its session without a handoff is surfaced to the next session in that repository, with the files and commits it left behind. `handoff.md` gains a procedure for writing it up from the record and git history, marked in Status as reconstructed after the fact. This inverts the failure: instead of the most exhausted agent writing the handoff, the next one does, with a full context window.
- `install.py` — registers both hooks in `~/.claude/settings.json`, which serves Claude Code and Zed's external `claude-acp` agent, and removes them on `--uninstall`; `--no-hooks` skips them. The settings file is backed up before any edit, only entries whose command matches Drift's own hooks path are touched, other hooks on the same events are left alone, key order and indentation survive, and a settings file that does not parse is refused rather than overwritten. A re-run after moving the clone repoints the commands instead of duplicating them.
- `handoff.md` — a "Session Records" section: read the record, take `session_started` and the `git diff` range from it, delete it once the artifact is written. New optional `session_started` frontmatter field, since `date` is when the handoff was written and that is a different fact.
- `SKILL.md` — a "Session Records" section covering what the hooks do and why a skill cannot do it.
- `README.md` — a "Session records" section before "Installing".
- `session-start.py --repo <path>` and `session-end.py --repo <path>` — the same record, opened and closed deliberately rather than by a hook, printed as plain text. For every harness with no hook mechanism: Zed's native agent, VS Code Copilot and Cursor. `session-end.py --repo <path> --session-id <id-from-start>` closes the exact record; omitting the ID only works for one unambiguous open manual record. Records opened this way are flagged `manual`.
- `SKILL.md` — instructs the agent to open a record itself when the session gave it none, so on a hookless harness this happens on the first Drift request rather than depending on the user knowing to run a command.
- **Zed's native agent gets an always-on surface after all: a marked Drift section in its personal `~/.config/zed/AGENTS.md`.** The native agent is not Claude Code and cannot have hooks, but Zed 1.18 replaced its Rules Library with a personal `AGENTS.md` that is included in every new thread — the binary injects it under a "Personal AGENTS.md" heading with project rules appended after. `install.py` now adds a section there, between `<!-- drift:start -->` and `<!-- drift:end -->`, telling the agent to run `session-start.py --repo .` before anything else and `session-end.py --repo .` if the user stops without a handoff, and to skip the first when a hook has already provided a record. Re-running updates a stale section in place and leaves everything outside the markers alone; `--uninstall` removes only the section and deletes the file if nothing else was in it; a symlinked file (a dotfiles-managed one, say) is written through rather than replaced; `--check` reports the section missing, out of date, or pointing at a missing script; `--no-hooks` skips it; a machine without Zed's config directory never sees it. The Windows path is `%APPDATA%\Zed\AGENTS.md`. This is an instruction the model follows, not a hook the harness enforces, and the docs say so — when it is skipped the record stays open and the next session is told, which is the same safety net the manual path already had. The other session's proposed fix was "a command the user runs at session start"; this is that command, run by the agent, from a file Zed loads for it.

### Fixed

- **Native Zed record instructions retain exact identity.** The personal `AGENTS.md` block now distinguishes actual current-thread startup output from its own heading, quoted handoffs and other-record notices; retains the exact ID/path across turns; closes with `--session-id`; and validates the handoff and index before consuming only its own record. Quoted interpreter paths support spaces. Four regressions cover the rendered commands, parallel-record closure, scoped/idempotent updates, backups and symlink preservation. Live model compliance remains a separate native-agent check in `TESTING.md`.
- **Dual-ACP installation audit.** Claude checks now reject stale matcher/type/timeout settings and malformed hook structures, while reinstall repairs Drift entries and leaves unrelated commands alone. Probes use a temporary Git repository as well as a temporary home, so concurrent edits in the live clone cannot contaminate a check. Added fresh bundled-agent, idempotence, scoped removal, settings/symlink preservation and smoke-environment regressions.
- **Copilot ACP's `sessionEnd: complete` is a turn completion, not a closed thread.** Confirmed with the real CLI 1.0.83 harness: the event fires after each turn, and deleting a no-change record loses the baseline before later work begins. Drift now keeps a `checkpointed` snapshot on that event, preserves it across turns and resume, and labels other threads' checkpoints as potentially still active. Explicit end reasons retain normal closing behavior.
- **Real hook field names and resume baselines.** Claude uses `source`/`reason`, not Drift's old `how`/`why` payload assumptions. Both formats are normalized, and resume no longer combines an old start time with a newly reset commit/fingerprint. A resumed closed record is reopened without losing its original baseline.
- **Same-size edits were invisible.** Working-tree fingerprints now include file-content hashes, modes and symlink targets; unchanged line counts and edits to existing untracked/binary files no longer hide work. Raw Git paths use filesystem decoding instead of the subprocess locale. Permission-denied files warn and use explicitly marked metadata-only fingerprints. Older records retain compatible rename-aware counts and quoted untracked paths.
- **Manual closure could take another thread's record.** Manual starts use unique IDs and print an exact close command. `--session-id` selects a record explicitly; the shorthand only closes one unambiguous manual record, never a harness-managed one.
- **Installer scope and probe isolation.** Explicit agent flags now scope hooks and rules as well as skill links, and Copilot's removable skill link is never used for a surviving Zed installation. Hook probes use temporary homes and unique IDs, exercise start and end, and never sweep real session records. Probes and both offline test scripts clear inherited Git repository/config overrides and isolate global configuration. Hook JSON writes preserve symlinks and use collision-resistant backups. Claude commands quote interpreter paths, recognize Windows separators, and upgrade Drift's matchers without changing another hook's matcher.
- **A session was credited with uncommitted work it merely found lying there.** `session-end.py` diffed against the session's *starting commit*, so opening a session in a dirty tree made it the owner of every pre-existing change. A two-second print-mode query in this repo reported ten changed files and became an orphan the next session would be told to write up. Both hooks now take a per-file `git diff HEAD --numstat` fingerprint plus the untracked list, at start and again at end, and the session is credited only with the difference. `--numstat` rather than a path set, so a file that was already dirty and got edited further is still detected. A session that changed nothing has its record deleted no matter what state the tree was in when it opened.
- **Records outlived the repositories they described.** Nothing ever removed them, so a record for a `/tmp` repo the smoke test had deleted sat there indefinitely and a long-lived machine accumulated them. `session-start.py` now sweeps on every run, dropping records whose repository no longer exists or that are older than thirty days, and removing directories left empty.
- **"Zed" was treated as one agent when it is two, and only one of them has hooks.** Zed ships an external `claude-acp` agent, which is the Claude Code binary and does fire the hooks — verified by replaying its exact argv, where the session emitted `hook_started` and `hook_response` for `SessionStart:startup`. It also ships a *native* agent, which resolves skills from `~/.agents/skills`, is not Claude Code, never reads `~/.claude/settings.json`, and has no hook mechanism of any kind. The docs generalised from the first to all of Zed. The correction cost two sessions: the first read "Claude Code hooks" and wrongly concluded Zed had none, the second read the over-corrected "Zed's agent is the Claude Code binary" and was wrongly told it should have them. `README.md` now carries a per-agent table, and `SKILL.md` and `install.py` name the agents rather than the editor.
- **`--check` implied end-to-end coverage it cannot have.** It reported hooks "registered and answering", but running the script by hand proves the script; only a live session proves the harness invokes it — which is exactly the failure mode on a harness with no hook mechanism, where every check the installer can make still passes. It now says "registered; script answers when run directly" and points at `~/.claude/drift-sessions/` as the only real evidence of invocation.
- `install.py --check` **runs the hook instead of trusting the registration.** It executes `session-start.py` with a synthetic payload, confirms it exits 0 and returns usable `additionalContext`, and deletes the record the probe created. A stale interpreter path or an unreadable script passed the old check.
- **An unclosed manual record was invisible.** The orphan notice skipped any record without an `ended` field, on the reasoning that an open record belongs to a session still running. That is true for hook-managed records and false for manual ones: the agents that open those have no session-end event, so they are never closed and would accumulate unseen. Open records marked `manual` are now surfaced, with the command to close them.
- `install.py` — when Zed is among the installed agents, the run explains that the hooks live in Claude Code's settings file for the external `claude-acp` runtime, not Zed's native agent. `hook_base()` now falls back to the Zed skill link when there is no Claude Code one, instead of dropping straight to the clone path.
- `.gitignore` — ignores `__pycache__/` and `*.pyc`. The hooks load `scripts/build-index.py` through `importlib` to reuse its frontmatter parsing, which byte-compiles it, so running a hook leaves `__pycache__` beside both files. Two `.pyc` files were committed with the hooks and have been removed.

## [0.3.0] - 2026-09-08

### Added

- **`install.py` — one command installs Drift for every supported agent on the machine.** Clone anywhere, run `python3 <clone>/install.py`, done. It detects Claude Code and Zed and symlinks each one's skills directory to the clone, so `git pull` in the clone is the upgrade and there is nothing to re-run; on Windows, where a symlink needs Developer Mode, it falls back to a directory junction. It is Python rather than shell because the repo already requires python3 for `scripts/build-index.py`, one script covers Arch, macOS and Git Bash on Windows, and the hook-registration step planned next is a JSON merge that shell cannot do safely. Behaviour is deliberately narrow: it creates nothing but those links (no project repo, no `.gitignore`, no agent settings, no sudo), re-running leaves anything already right alone and says so, `--dry-run` prints the same plan the real run would execute, `--check` reports the install state with a non-zero exit on any fault, `--uninstall` removes only links that point at this clone and leaves anything else with a reason, and a real directory in the way is reported and never removed unless `--force` moves it aside as `drift.bak-<timestamp>`. Running it from a clone that already sits at a skills path is recognised as installed in place. Exercised against a throwaway `$HOME` for fresh install, re-run, stale-link repoint, conflict, forced move, in-place clone, check, dry-run and uninstall.
- `README.md` — "Installing" now leads with the two-line clone-and-run; the Claude Code and Zed rows point at the installer, VS Code and Cursor stay manual. "Developing Drift itself" collapses to the same command, since the dev setup and the user setup are now one symlink made the same way.
- **`scripts/smoke-test.sh` — an end-to-end check that the install actually works**, as opposed to the links merely resolving. It runs `install.py --check`, finds a Claude Code binary (the `claude` CLI, or the one Zed bundles on Linux and macOS), asks a print-mode session to list its skills and confirms `drift` is among them, then runs a real Drift research pass in a throwaway repo under `/tmp` and verifies what came out: the artifact exists, its `date` is a full clock read with an offset, `git_commit` is a 40-character hash, `INDEX.md` carries the row, and `.gitignore` gained `/drift/`. The repo is deleted afterwards. Without a binary it runs the link check and says to try `/drift` in a new session. Two things it surfaced while being written: `claude -p --allowedTools` is variadic and silently swallows a positional prompt, so the script feeds prompts on stdin; and the agent hand-writes `INDEX.md` with the right row but its own header prose, so `build-index.py --check` reports it out of date. The script reports that as a note, not a failure, since it is a Drift design issue rather than an install fault.
- **`SKILL.md` — "Timestamps" section requiring `date` to be read from the system clock**, with `date -Iseconds` and a portable `python3` equivalent (BSD/macOS `date` has no `-I`). Drift previously specified the frontmatter date's *format* and never said where to get the value; an agent has no clock, so it filled one in. Audited against git, one repo's 86 artifacts held 34 provably impossible dates — several claiming a time hours *after* the commit the same artifact recorded as `HEAD`, a hash that could not have existed yet. The section names the three observed failure modes (a date-only harness value padded to `T00:00:00`; forward-compounding drift from extrapolating off the previous artifact; an invented round session start where there was no anchor), requires the machine's real offset rather than hand-normalizing to `Z`, and says to record day precision and mark it approximate when no clock is reachable. False precision outranks real evidence; honest coarseness does not.
- `research.md` / `plan.md` / `handoff.md` — the same instruction inline beneath each frontmatter block, so each prompt is self-sufficient when read as active workflow instructions.
- `README.md` — note in "The running order" that index ordering is only as good as its timestamps, linking the new section.
- **`drift/INDEX.md` — a root chronological index of every artifact in the repo.** Feature folders show a feature's own narrative, but each folder's `NNN` counts from `001`, so the file tree stops being a timeline once a repo has more than a few features and interleaved work becomes invisible. The index is one table, oldest first, with a global running `#` that is deliberately independent of the folder-local sequence. Rows sort on the **UTC-normalized instant** of each artifact's frontmatter `date`, not the raw string — a repo worked on from more than one machine mixes offsets, and `2026-08-31T00:00:00Z` is an hour *after* `2026-08-31T00:00:00+01:00`. Ties break on feature then sequence so rebuilds are stable.
- `SKILL.md` — "Root Index" section: format, column and ordering rules, the append-on-write rule, and a rebuild procedure covering artifacts with no parsable `date` (fall back to a body date and mark approximate, or list under `## Undated`) and legacy subfolder paths.
- `scripts/build-index.py` — stdlib-only rebuild helper for the index; takes a project's `drift/` directory, with `--check` to report an out-of-sync index without writing. First script in the repo, matching the Agent Skills convention of `SKILL.md` plus optional `scripts/`: judgment stays in the prompts, deterministic work moves to a tool. `SKILL.md` still specifies the format, so an agent without a shell can rebuild the index by following the procedure.
- `README.md` — "The running order" section explaining why the index exists and how `#` relates to `NNN`.
- `handoff.md` / `execute.md` — resuming now skims the tail of the index for work landed in *other* features since the artifact being resumed was written, so a stale plan is noticed rather than followed blindly.
- `README.md` — "Developing Drift itself" section: symlink `~/.agents/skills/drift` to a working clone for a single source of truth when developing the prompts while using the skill, with the known-good-state tradeoff called out.
- `execute.md` — fourth mode. Orchestrates a plan or handoff: walks the step sequence, delegates self-contained steps to sub-agents (parallel where write scopes are disjoint), verifies each step, and hands off via `handoff.md` at the end. Includes delegation heuristics (delegate scoped multi-file work; keep verification, one-shot edits, and tightly-coupled iteration with the orchestrator) and a sub-agent prompt skeleton. Supports both flat numbered inputs and legacy subfolder paths; output handoffs always follow the flat numbered convention unless the user explicitly asks to preserve a legacy chain.
- `SKILL.md` — router entry and workflow step for the new `execute.md` mode.
- `README.md` — "Executing" section, mermaid updated to include the execute node with a resume edge from handoff, install-table invocations updated to include `/execute`.
- Drift artifact writing now ensures the repository-root `.gitignore` exists and includes `/drift/` before creating project-local Drift output folders.
- `SKILL.md` — reusable skill entrypoint for agents that support global skill directories such as `~/.agents/skills`
- `README.md` — "When not to use Drift" section
- `README.md` — reusable skill installation instructions and "Installing as reusable commands or skills" table covering Zed Agent, VS Code Copilot, Claude Code, Cursor, and paste-into-chat
- `README.md` — explicit guidance to summarize completed phases when handoff chains exceed three documents
- `README.md` — illustrated flat numbered artifact files inside `drift/<feature>/` in "Where files are stored"
- `examples/` directory (placeholder for future example artifacts)

### Removed (breaking)

- **The "paste anywhere" operating model.** Drift no longer presents itself as markdown you can paste into any chat. `README.md` drops the "No skill support? Use the files directly" fallback, the "Where these work" section, and the `Anything else → paste into the chat` install row. Pasting a single prompt was never equivalent: the workflow depends on `SKILL.md` routing between prompt files, the agent reading and writing artifacts under `drift/`, and now a script to rebuild the index — none of which survive a copy/paste. Tools without a skill or prompt-file directory are explicitly unsupported rather than half-supported.
- `README.md` — "Installing as reusable commands or skills" renamed to "Installing" (anchor updated in Getting Started), reordered to lead with Claude Code, and rewritten to state the requirement up front.

### Changed (breaking)

- **Maintaining a root index is now required, reversing the previous prohibition.** `SKILL.md` and `README.md` previously said Drift does not maintain `INDEX.md`; that applied navigation-by-filename reasoning to the cross-feature case, where it does not hold. Per-feature `CURRENT.md` files and `active/`/`done/` status directories are still out. Existing projects need no migration — the index is a derived view, so rebuild it from frontmatter.
- `research.md` / `plan.md` / `handoff.md` — "Writing to Disk" now includes appending the new artifact's index row, and rebuilding the index if it has fallen out of sync. Part of writing an artifact, not a separate request.
- `execute.md` — index rows are the orchestrator's job alongside the handoff; sub-agents must not write either.
- **Prompt filenames shortened** to `research.md`, `plan.md`, `handoff.md` (from `research-codebase.md`, `plan-from-research.md`, `mid-work-handoff.md`). Frontmatter `name:` values updated to match. Slash-command invocations are now `/research`, `/plan`, `/handoff` across all supported tools.
- **Artifact paths restructured to flat numbered files inside feature folders: `drift/<feature>/NNN-research-topic.md`, `drift/<feature>/NNN-plan-description.md`, and `drift/<feature>/NNN-handoff-description.md`** — replaces the previous top-level `research/`, `.handoffs/<TICKET>/`, and split `drift/<feature>/research/` / `handoffs/` layouts for new work. Existing subfolder layouts remain legacy-supported when resuming from an existing artifact path.
- All three prompts now require the agent to confirm/derive a **feature identifier** before writing. Ticket reference or descriptive slug — anything unique — is used as the folder name under `drift/<feature>/`, while artifact files receive the next three-digit sequence number.

### Changed

- `README.md` — Claude Code install switched from four copied commands in `.claude/commands/` to a single skill at `~/.claude/skills/drift` (or `.claude/skills/drift` for project scope), invoked as `/drift` and routed by `SKILL.md`. Matches the skills-by-default model and `SKILL.md`'s "do not split Drift into separate global skills" rule.
- `README.md` — reframed around a skills-by-default operating model. "Getting Started" now leads with installing Drift as a reusable agent skill (tool-agnostic, with concrete per-tool paths deferred to the compatibility table) and demotes copy/paste to a "no skill support?" fallback covering both file-linking and pasting. Workflow step callouts (Research / Plan / Execute / Handoff) reworded from "Paste [x.md]" to "Ask Drift to …", with the underlying prompt file linked for paste-mode users.
- `plan.md` — Implementation Sequence items must now be self-contained enough to hand to a sub-agent (clear files, clear goal, clear verification). Guidelines call out disjoint scopes so an orchestrator running the plan via `execute.md` can parallelize where safe.
- `SKILL.md` now acts as a single router entrypoint for research, planning, handoff, and resume requests
- Renamed `from-research.md` → `plan-from-research.md` (subsequently shortened to `plan.md` — see above)
- Frontmatter `name:` values match filenames so VS Code prompt-file tooling resolves them correctly
- `research.md` — research output now includes `date` / `branch` / `git_commit` / `type` frontmatter, matching the handoff prompts
- All three prompts — "Writing to Disk" sections now include an explicit **Path verification** subsection enumerating forbidden destinations (editor memory, temp dirs, user-profile paths, absolute paths outside the repo)
